# LanDrop · 局域网快传

> 像 XFTP 一样左右双栏，但专为家里几台 Windows 电脑设计。  
> 同一个 Wi-Fi 下双击即用，文件只在局域网内传输，不经过微信、网盘或互联网。

![LanDrop 主界面](docs/screenshot-main.png)

## 它解决什么问题

用微信/QQ 传文件，需要登录、加好友、压缩、等对方点接收，还会过期和限速。  
LanDrop 的做法更直接：

- 每台 Windows 电脑运行一个免安装的 `LanDrop.exe`；
- 自动发现同一局域网里的其他电脑；
- 输入一次对方的连接码完成配对；
- 左边是“本机”，右边是“对方电脑”，像本地文件管理器一样浏览；
- 选中文件或文件夹，点一下就开始传，底部显示实时进度和速度。

文件由两台电脑直接传输，不经过浏览器中转，也不上传到任何服务器。

## 功能一览

| 功能 | 说明 |
| --- | --- |
| 免安装 | 单个 `LanDrop.exe`，不需要安装 Python、Node.js 或数据库 |
| 自动发现 | 同一 Wi-Fi 下通过 UDP 广播发现设备，也支持手动输入 IP |
| 双栏浏览 | 本机 / 对方电脑，双击进入文件夹，支持磁盘切换、路径跳转、筛选 |
| 文件 + 文件夹 | 文件夹会递归传输，保留子目录结构 |
| 传输队列 | 实时进度、速度、当前文件；支持取消和清除已完成 |
| 同名保护 | 目标位置已有同名文件时自动生成 `文件名 (1).ext`，不覆盖 |
| 连接码 | 首次配对需要连接码；之后记住设备，一键连接 |
| 隐私 | 传输界面只允许本机打开；局域网接口需要连接码 |
| 托盘运行 | 关闭浏览器后程序继续在托盘运行，可设置开机启动 |
| 中文路径 | 支持中文、空格、长文件名和常见大文件 |

## 快速开始

### 1. 准备

需要 **Windows 10 / 11**（系统自带 .NET Framework 4.8）。  
把 `LanDrop.exe` 复制到每台需要传文件的电脑上，建议放在固定目录，例如：

```text
D:\LanDrop\LanDrop.exe
```

不需要安装，也不需要联网。

### 2. 在每台电脑上运行

双击 `LanDrop.exe`：

- 如果 Windows 弹出 **“Windows 已保护你的电脑”**，点“更多信息” → “仍要运行”；
- 如果 Windows 防火墙弹出提示，请勾选 **“专用网络”** 并点 **“允许访问”**（这一步很重要，否则其他电脑连不上）；
- 程序会打开浏览器页面 `http://127.0.0.1:52180/`，并在右下角托盘显示 LanDrop 图标；
- 页面右上角会显示本机连接码，例如 `ABCD-EFGH`。

> 如果端口 52180 被占用，程序会自动尝试 52181、52182……  
> 实际端口显示在“设置”里；手动添加设备时填实际端口。

### 3. 配对两台电脑

假设 A 电脑已经打开 LanDrop，现在在 B 电脑上操作：

1. 点右侧“对方电脑”里的 **“添加设备”**；
2. 在“附近设备”里选中 A 电脑；
3. 输入 A 电脑右上角的连接码；
4. 点“连接”。

如果附近设备列表为空：

1. 切到 **“手动输入 IP”**；
2. IP 填 A 电脑顶部显示的地址（例如 `192.168.1.23`）；
3. 端口填 A 电脑“设置”里显示的端口（默认 `52180`）；
4. 输入连接码，点“连接”。

配对成功后，B 会记住 A。以后打开 LanDrop 会自动选中上次连接的设备。

> 两台电脑必须连同一个路由器/同一个 Wi-Fi，并且路由器没有开启“AP 隔离/访客网络隔离”。  
> 电脑的网络类型建议设为“专用网络”，不要设为“公用网络”。

### 4. 传文件

界面左边是 **本机**，右边是 **对方电脑**。

- 双击文件夹进入；点上方“此电脑”或磁盘下拉框切换磁盘；
- 单击文件/文件夹选中；按住 `Ctrl` 可多选，也可以勾选左侧复选框；
- 选中左侧项目，点 **“传到对面 →”**；
- 选中右侧项目，点 **“← 下载到本机”**；
- 文件夹会连同里面的所有子文件一起传输；
- 底部“传输队列”会显示进度、速度和当前文件；可以展开、取消或清除已完成任务。

传输过程中可以继续浏览文件，也可以关闭浏览器页面——传输由托盘里的程序继续执行。

## 常见问题

### 对方设备一直不出现

按顺序检查：

1. 两台电脑都打开了 LanDrop，托盘图标还在；
2. 在同一个 Wi-Fi / 同一网段（例如都是 `192.168.1.x`）；
3. Windows 防火墙允许了 LanDrop 的“专用网络”访问；
4. 路由器没有开启 AP 隔离或访客网络；
5. 仍不行就点“手动输入 IP”，用对方顶部显示的地址连接。

### 提示“无法连接”或“连接超时”

- 在 A 电脑上打开命令提示符，执行 `ping B的IP`，确认能通；
- 确认 B 电脑的 LanDrop 还在托盘运行；
- 确认没有把“公用网络”当成“专用网络”；
- 检查安全软件是否拦截了 `LanDrop.exe` 的入站连接；
- 端口可能不是 52180，以对方“设置”里显示的为准。

### 传输失败：目标文件夹没有写入权限

- 对方的目标文件夹可能是系统保护目录（如 `C:\Program Files`、`C:\Windows`）；
- 换到桌面、文档或用户目录下的文件夹；
- 检查对方磁盘是否已满；
- 检查文件是否被 Excel、Word、播放器等程序独占打开。

### 速度慢

- 优先使用 5 GHz Wi-Fi；条件允许时用网线；
- 大量小文件比单个大文件慢，这是正常的；
- 传输时避免同时下载/看视频；
- 速度取决于路由器和两台电脑的网卡，不取决于 LanDrop。

### 关闭浏览器后还在传吗？

在。传输由托盘里的 `LanDrop.exe` 执行，浏览器只是控制界面。  
要彻底停止程序，右键托盘图标 → **“退出 LanDrop”**。

### 需要联网吗？

不需要。LanDrop 只使用局域网；没有云端账号，也不会把文件名或内容上传到互联网。

### 安全吗？

- 传输界面只能在本机 `127.0.0.1` 打开；
- 其他电脑访问文件接口必须提供连接码换取的凭据；
- 连接码相当于“文件访问钥匙”，拿到连接码的人可以浏览和修改你允许访问的文件；
- **只在可信的家庭局域网使用**，不要在公共 Wi-Fi 或陌生网络中开启；
- 不要把连接码发给陌生人。

## 数据与卸载

配置、日志和运行信息在：

```text
%APPDATA%\LanDrop\
```

其中：

- `config.json`：设备名、连接码、已配对设备；
- `landrop.log`：运行日志（排错时看这个）；
- `endpoint.txt`：当前界面地址。

卸载：

1. 右键托盘图标 → “退出 LanDrop”；
2. 在“设置”里关闭“开机自动启动”；
3. 删除 `LanDrop.exe`；
4. 如需彻底清除配对信息，再删除 `%APPDATA%\LanDrop` 文件夹。

> 删除 `config.json` 会重置连接码和所有已配对设备，需要重新配对。

## 技术说明

- 语言/运行时：C# + .NET Framework 4.8，WinForms 托盘程序；
- 单文件：Web 界面、图标全部嵌入 `LanDrop.exe`；
- HTTP 服务：自建轻量 TCP HTTP 服务，默认端口 `52180`（被占用时自动顺延）；
- 设备发现：UDP 广播，端口 `52181`；
- 传输方式：两台电脑的 LanDrop 服务端直接收发，浏览器只负责发指令；
- 界面：原生 HTML/CSS/JavaScript，无外部 CDN 依赖。

源码结构：

```text
LanDrop/
├─ src/                 C# 源码
├─ web/                 前端页面
├─ assets/              图标
├─ build.ps1            编译 / 打包脚本
├─ app.manifest         Windows 清单
├─ dist/LanDrop.exe     编译产物
└─ docs/                说明图片
```

重新编译（Windows 自带 .NET Framework 编译器即可）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

输出：

```text
dist\LanDrop.exe
release\LanDrop-1.0-Windows.zip
release\LanDrop-1.0\
```

如果只想编译、不打包：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -NoPackage
```

### GitHub Actions 自动构建

仓库已包含 `.github/workflows/build.yml`。推送到 GitHub 后：

1. 打开仓库的 **Actions** 页面；
2. 选择 **Build Windows executable**；
3. 运行完成后，在 **Artifacts** 里下载 `LanDrop-windows`。

每次 push 和 pull request 也会自动编译并检查。

### 上传到 GitHub

源码包解压后就是一个完整的仓库目录，可直接用 GitHub 网页上传，或按 [GITHUB_UPLOAD.md](GITHUB_UPLOAD.md) 里的 Git 命令推送。

`dist/`、`release/`、`*.exe` 已被 `.gitignore` 排除，不需要把编译产物提交进仓库；GitHub Actions 会自动生成。

### 开发者参数

正式使用不需要这些参数，调试时可用：

```text
--port 53000              指定 HTTP 端口
--data-dir D:\Temp\A      指定配置目录（便于一台电脑同时开多个实例）
--no-browser              启动后不自动打开浏览器
--no-discovery            关闭 UDP 自动发现（仍可手动输入 IP）
```

调试版本可用 `build.ps1 -DebugBuild` 编译为控制台程序。
